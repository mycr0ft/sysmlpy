## 0.104.2 (2026-11-04)

- **Cold analyze: 190 s → 10.9 s** (0.103.3 was 43.5 s).  The snapshot was only
  consulted when `lib_roots` was None, but `analyze(model, library=[...])` —
  the ordinary path — always passes explicit roots, so a cold analyze rebuilt
  the whole facts index (276 s with no DFA cache).  The snapshot is now tried
  for any roots and accepted only when its digest matches theirs: a custom
  library fails the check and builds; the bundled library answers instantly

## 0.104.1 (2026-11-04)

- **Shipped facts snapshot: first run 276 s → 0.02 s.** The library facts index
  is now packaged as `src/sysmlpy/library_facts.json` (564 KiB, generated by
  `scripts/gen_library_facts.py`), validated against build id + library content
  digest like any cache record — a stale snapshot is a *miss*, never wrong
  answers, and custom library roots never use it.  The measured cold build from
  source is 276 s on a machine with no DFA cache (each parse pays DFA
  construction), which is why a snapshot is the difference between a usable first
  run and a four-minute wait.  Same approach as OpenSysML's `stdlib.snapshot`.
- `tests/library_facts_test.py` fails when the snapshot does not match the
  current build id or library digest, so a version bump or a library edit cannot
  silently ship a stale one.
- Pool workers no longer touch the persistent DFA cache
  (`ProcessPoolExecutor(initializer=_worker_init)`): eight workers each loading
  and re-saving a tens-of-MB pickle was serialising the parallel extract.

## 0.103.3 (2026-11-03)

- **Issue #41: a succession vanished when its body had other members.**
  `part p { first a then b; }` kept it; add one sibling —
  `part p { attribute x : Real; first a then b; }` — and it disappeared from the
  element tree *and* the dump. The parse tree and the visitor dict both carried
  it, so the loss was in the loader: no child element was built for a
  `Succession`, and `Usage._ensure_body` rebuilds a parsed body from
  `self.children`. Alone, the body had no other member and the grammar body
  survived by accident.

  A succession is now a first-class element, modelled the way `Binding` already
  is (a non-occurrence usage kept in the tree, `DefinitionBodyItem →
  NonOccurrenceUsageMember → NonOccurrenceUsageElement` on the way back), with
  `source` / `target` / `ends` readable from the connector ends:

  ```python
  p.children                     # [Attribute('x'), Succession(None)]
  p.children[1].source, .target  # ('a', 'b')   — chains too: ('a.b', 'c.d')
  ```

  The `succession` keyword is preserved, multiple successions keep their order,
  and any position in the body works (first, middle, last).

- Library sweep stays clean: 58 files, 0 parse failures, 0 non-idempotent, 0 raw
  dicts, 0 stdout noise.

- Pins: `tests/issue41_test.py` (11).

## 0.103.2 (2026-11-03)

- **Issue #40: the last four defects keeping library dumps from round-tripping.**
  With these fixed, **all 58 `.sysml` files in `src/sysmlpy/library` load, dump,
  re-parse to identical text, contain no raw dicts, and print nothing.**
  Measured on the 0.103.1 wheel against the 0.103.2 tree:

  ```
                before   after
  parse failures    1       0      Actions.sysml (reparse returned None)
  not idempotent    2       0      SampledFunctions, VerificationCases
  raw dicts         0       0
  stdout noise      2       0      AnalysisCases, Cases
  ```

  1. **`then perform body;` lost its target** (`Actions.sysml` — the one file
     that failed to re-parse at all). The visitor's behavior-member dispatch had
     no `performActionUsage` branch, so the member vanished and the dump emitted
     a bare `then ;`, which the grammar rejects. The member now loads as
     `BehaviorUsageMember → BehaviorUsageElement → PerformActionUsage`.
  2. **Preserved text collapsed newlines** (`SampledFunctions.sysml`). A
     constraint body with a trailing `//` comment was flattened onto one line, so
     on the next parse the comment swallowed the rest of the expression and the
     body fell back to captured text. `_verbatim_text` now collapses whitespace
     *within* lines and keeps the line breaks.
  3. **Ternary re-spacing was not idempotent** (`VerificationCases.sysml`).
     `_respace_ternary_glue` re-spaced already-spaced text, adding a space per
     round trip (`if  passing  ? …`). It now strips each part before re-joining.
  4. **`case`/`analysis` usages were dropped and printed to stdout**
     (`AnalysisCases.sysml`, `Cases.sysml`). `Package.load_from_grammar` had no
     `CaseUsage`/`AnalysisCaseUsage` branch ("Unknown class … skipping"), and the
     case-family declaration (name + typing) lives in a
     `constraintUsageDeclaration` that the name helper never read — `case c1 :
     CD;` came out as `case;`. Both now load with their names.

- Pins: `tests/issue40_test.py` (9), including the whole-library sweep as the
  acceptance criterion.

## 0.103.1 (2026-11-03)

- **Issue #36: metadata applications now state themselves in the `@graph`.**
  Two shape decisions, both taken against what the implementations actually
  emit — the OMG metamodel generated into `SysML-v2-API-Services`
  (`MetadataUsage extends ItemUsage, MetadataFeature`; `Annotation` carries
  `annotatedElement`/`annotatingElement`), OpenSysML's
  `docs/reference/rdf-mapping.md`, and sysml-toolkit's `INTEROP.md`:
  - **Metaclass (`D'`)**: an annotation node is now typed **`MetadataUsage`**,
    the SysML metaclass, instead of the bare KerML `MetadataFeature`. The two
    are related by inheritance, so a consumer keyed on either finds it.
  - **Link (`B'`)**: the annotation node carries
    `"annotatedElement": [{"@id": <the element it annotates>}]` — the metaclass
    property, on the annotation (not a convenience edge on the anchor, which is
    what I first proposed and then withdrew after checking the tools). For the
    body form the anchor is the element whose body holds the application; for
    the `#M` prefix form, the element being prefixed; for nested elements, the
    nearest one.
  - **Sigil**: `"declaredKeyword": "@" | "#"` records which form the author
    wrote (the visitor now captures it; `metadata m : M;` normalises to `@`,
    which is what its own dump already did).
  - An annotation with an `about` clause keeps its `Annotation` nodes and gets
    **no** derived edge — that clause names its own targets, and the ownership
    edge would state something false.

  Nothing enters the identity space: element ids are byte-identical to 0.103.0
  (95/95 nodes on the probe model), `stable_ids`/`doc_ids`/`reconcile_ids` are
  untouched, `explicit_terms=True` picks the new terms up automatically, and a
  pre-0.103.1 document (typed `MetadataFeature`, no derived edge) still imports
  unchanged.

## 0.103.0 (2026-11-03)

- **Issue #39: binding connectors lost their `binding` keyword and
  multiplicity** — the last blocker for a clean library. Three causes:
  1. the connector's usage-declaration multiplicity (`[1]`) was never read by
     the visitor, so `binding [1] bind …` dumped as `binding  bind …`;
  2. `BindingConnector.dump()` appended the *anonymous* declaration as its own
     token, which is where the double space (and the "the keyword only survives
     by accident" look) came from;
  3. a bare `bind …` was indistinguishable from `binding bind …`, so the dumper
     could invent the keyword. It now travels with the dict
     (`hasBindingKeyword`), and a bare `bind` stays bare.

  The connector's `usageBody` was also hardcoded empty, so members inside
  `binding … { members }` were dropped; they load now.

- **`Succession` had the same two defects** (dumped as `succession  first …`,
  and the optional `succession` keyword was unconditional — `first a then b;`
  came back as `succession first a then b;`). Same fix, same flag. This is what
  made `systems/Flows.sysml` non-idempotent.

- **Library sweep (58 files) after the fix**: 0 raw dicts, and the four
  Quantities/Geometry files plus `systems/Flows.sysml` are clean fixed points.
  Residual stragglers, each its own defect, are filed as **#40**:
  `Actions.sysml` (a succession's `perform` target is dropped → parse error),
  `SampledFunctions.sysml` (an indexed `#(i)` expression emits text the grammar
  rejects), `VerificationCases.sysml` (`if  cond ?` whitespace not normalised),
  and the `CaseUsage`/`AnalysisCaseUsage` skips that print on dump.

- Pins: `tests/issue39_test.py` (21).

## 0.102.8 (2026-11-02)

- **Issue #33: grouped exponents were opaque text — calc bodies were
  unevaluable, and unit-expression exponents dumped raw dicts.** A
  parenthesized group had no representation in the expression chain, so the
  emitter fell back to preserving the whole expression as one name:
  `(x^(1/2)+0)` reached the evaluator as the identifier `(x^(1/2)+0)`. It is now
  represented structurally — a `PrimaryExpression` whose base is a
  `SequenceExpression` relationship, the shape `BaseExpression.dump()` already
  renders in parentheses — so the group is *one operand* of whatever encloses
  it:
  - `(x^(1/2)+0)` at `x=9` → **3.0**; `(a+b)^2` → 25.0; `(x*(1+y))^2` → 64.0;
    results stay pint-aware (`x * 2 [m]` → `Quantity(6.0, 'meter')`).
  - The `#31` paren guards are gone: with a real paren node the emitter no
    longer needs a binding-power heuristic, and `tp / (tm * v)`, `-(2 - 5)` and
    `(a or b) and c` all dump as written and are now *structured* rather than
    text.
  - Two dumper defects behind the raw-dict leak:
    `ExponentiationExpression.dump()` converted its right operand as another
    `ExponentiationExpression` (the grammar says `unaryExpression`), so
    `x ^ 2` printed `x ^ {'name': 'UnaryExpression', ...}`; and
    `MultiplicativeExpression.dump()` joined operands with `""`
    (`tp/ (tm* v)`). Both fixed.
  - `const_fold` folds through groups (nested `OwnedExpression`,
    `SequenceExpression`), and the evaluator accepts `^` (SysML spelling) as
    well as `**`.
  - Library effect: the four files that leaked dicts are clean —
    SI.sysml 1085 → 0, USCustomaryUnits 325 → 0, SIPrefixes 35 → 0,
    ShapeItems 104 → 0 — and dump without any stdout output.
  - Pins: `tests/issue33_test.py` (27).

- **Issue #32: keyword-less variant members kept their body at grammar level.**
  `variant 'six cyl' { attribute note : String; }` built the variant element but
  loaded no children, because `Reference.load_from_grammar` returned before the
  shared body dispatch. The dispatch loop in `Usage.load_from_grammar` is now
  `Usage._load_body_members`, and the VariantReference branch unpacks its
  `UsageBody → DefinitionBody` members and loads them through it, so
  `variant.children` really holds the members.
  - Same gap in **action** bodies: `variation action g : A { variant g1; }`
    parsed as `ActionBodyItem → VariantUsageMember`, which neither the visitor
    nor `Action.load_from_grammar` dispatched — the variants existed only in
    the grammar. The visitor now visits `VariantUsageMemberContext`, and the
    action loader routes those members through the shared dispatch with the
    variant chain marked (`is_variant` True). On the OMG corpus this restores
    all four `variant generateTorque*/amplifyTorque*` members.
  - Pins: `tests/issue32_test.py` (9), including the OMG
    VehicleVariabilityModel round-trip.

- **New issue #38 filed** (found here): multiple redefinitions are dumped
  space-joined without repeating `:>>`, which is why SI.sysml / USCustomaryUnits
  / ShapeItems still do not re-parse even with no raw dicts left.

## 0.102.7 (2026-11-02)

- **Issue #31: `assert constraint` bodies dumped glued operators and never
  reached a fixed point.** Three separate defects in the expression emitter —
  only the third was in the report:
  1. **Wrong operand class for the loose boolean layers.**
     `_unwrap_to_layer` handed `OrExpression` the And-layer, `XorExpression`
     the Or-layer and `ImpliesExpression` the tail of a ladder, but each layer's
     grammar class expects the layer immediately BELOW it
     (`orExpression : xorExpression (OR xorExpression)*`). Any expression using
     `or`/`xor`/`implies` therefore put a foreign chain dict into an operand
     slot and the dumper stringified it:
     `a xor b` → `a xor {'name': 'OrExpression', 'operator': [], ...}`.
     Corrected for OR (→ xor), XOR (→ and) and IMPLIES (→ or).
  2. **Parenthesized groups never entered the chain.** `(A and B) xor (C and D)`
     matched no emitter branch, so the *whole* expression collapsed to one
     FeatureReference name. Groups are now unwrapped
     (`_paren_inner_context`, which follows the
     `ownedExpression → primaryExpression → baseExpression → '('
     sequenceExpressionList ')'` wrappers). A group keeps its parens whenever
     its loosest operator binds **no tighter** than the enclosing operator —
     at equal precedence the parens still decide the grouping
     (`tp / (tm * v)` must not become `tp / tm * v`, `-(2 - 5)` must not become
     `-2 - 5`), and a unary prefix over a grouping stays text for the same
     reason.
  3. **The text fallback glued tokens.** `ctx.getText()` concatenates tokens,
     so any preserved expression became unparseable
     (`(a or b) and c` → `(aorb)andc`). The fallback now slices the original
     source (`_verbatim_text`, whitespace-normalised) using the context's
     character interval, so preserved text is the source text.
- **Dumps no longer print on stdout.** `valid_definition` printed the offending
  dict's `name` before raising — on a normal control-flow miss (probing an
  operand against several layer classes). It flooded `sysmlpy ci` with layer
  names; the raise stays, the print is gone.
- Corpus: `VehicleVariabilityModel.sysml` (the reporting file) now reaches a
  fixed point with **no** `language "English"` capture and an operator sequence
  identical to the source (21 operators, `==`/`and`/`xor`).
- Gate: 0 parse failures, **1180** errors (was 1183) / 1706 warnings, PASS —
  the three former text-captured bodies now expose their identifiers to the
  resolver, retiring 5 `UNRESOLVED_EXPRESSION_IDENTIFIER` findings.
- Pins: `tests/issue31_test.py` (11). Known and unchanged: unit-expression
  exponents (`s ^ -1`, `1024 ^ (1/1000)`) still dump their `UnaryExpression`
  dict — a pre-existing leak tracked by issue #33, which the same machinery
  now makes tractable.

- **Issue #34 step 7: the `.kerml` half of the library now answers on truth.**
  KerML names were only ever *scraped* — `exists_in_loaded_model` returned

  - Pins: `tests/issue34_step7_test.py` (7 — member tables, kernel namespaces,
