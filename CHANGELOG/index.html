    CHANGELOG¶

    0.103.2 (2026-11-03)¶

    • Issue #40: the last four defects keeping library dumps from round-tripping. With these fixed, all 58 .sysml files in src/sysmlpy/library load, dump, re-parse to identical text, contain no raw dicts, and print nothing. Measured on the 0.103.1 wheel against the 0.103.2 tree:
                  before   after
parse failures    1       0      Actions.sysml (reparse returned None)
not idempotent    2       0      SampledFunctions, VerificationCases
raw dicts         0       0
stdout noise      2       0      AnalysisCases, Cases
    1. then perform body; lost its target (Actions.sysml — the one file that failed to re-parse at all). The visitor's behavior-member dispatch had no performActionUsage branch, so the member vanished and the dump emitted a bare then ;, which the grammar rejects. The member now loads as BehaviorUsageMember → BehaviorUsageElement → PerformActionUsage.
    2. Preserved text collapsed newlines (SampledFunctions.sysml). A constraint body with a trailing // comment was flattened onto one line, so on the next parse the comment swallowed the rest of the expression and the body fell back to captured text. _verbatim_text now collapses whitespace within lines and keeps the line breaks.
    3. Ternary re-spacing was not idempotent (VerificationCases.sysml). _respace_ternary_glue re-spaced already-spaced text, adding a space per round trip (if passing ? …). It now strips each part before re-joining.

    4. case/analysis usages were dropped and printed to stdout (AnalysisCases.sysml, Cases.sysml). Package.load_from_grammar had no CaseUsage/AnalysisCaseUsage branch ("Unknown class … skipping"), and the case-family declaration (name + typing) lives in a constraintUsageDeclaration that the name helper never read — case c1 : CD; came out as case;. Both now load with their names.

    5. Pins: tests/issue40_test.py (9), including the whole-library sweep as the acceptance criterion.

    0.103.1 (2026-11-03)¶

    • Issue #36: metadata applications now state themselves in the @graph. Two shape decisions, both taken against what the implementations actually emit — the OMG metamodel generated into SysML-v2-API-Services (MetadataUsage extends ItemUsage, MetadataFeature; Annotation carries annotatedElement/annotatingElement), OpenSysML's docs/reference/rdf-mapping.md, and sysml-toolkit's INTEROP.md:
    • Metaclass (D'): an annotation node is now typed MetadataUsage, the SysML metaclass, instead of the bare KerML MetadataFeature. The two are related by inheritance, so a consumer keyed on either finds it.
    • Link (B'): the annotation node carries "annotatedElement": [{"@id": <the element it annotates>}] — the metaclass property, on the annotation (not a convenience edge on the anchor, which is what I first proposed and then withdrew after checking the tools). For the body form the anchor is the element whose body holds the application; for the #M prefix form, the element being prefixed; for nested elements, the nearest one.
    • Sigil: "declaredKeyword": "@" | "#" records which form the author wrote (the visitor now captures it; metadata m : M; normalises to @, which is what its own dump already did).
    • An annotation with an about clause keeps its Annotation nodes and gets no derived edge — that clause names its own targets, and the ownership edge would state something false.

    Nothing enters the identity space: element ids are byte-identical to 0.103.0 (95/95 nodes on the probe model), stable_ids/doc_ids/reconcile_ids are untouched, explicit_terms=True picks the new terms up automatically, and a pre-0.103.1 document (typed MetadataFeature, no derived edge) still imports unchanged.

    • Pins: tests/issue36_test.py (11).

    0.103.0 (2026-11-03)¶

    • Issue #39: binding connectors lost their binding keyword and multiplicity — the last blocker for a clean library. Three causes:
    • the connector's usage-declaration multiplicity ([1]) was never read by the visitor, so binding [1] bind … dumped as binding bind …;
    • BindingConnector.dump() appended the anonymous declaration as its own token, which is where the double space (and the "the keyword only survives by accident" look) came from;
    • a bare bind … was indistinguishable from binding bind …, so the dumper could invent the keyword. It now travels with the dict (hasBindingKeyword), and a bare bind stays bare.

    The connector's usageBody was also hardcoded empty, so members inside binding … { members } were dropped; they load now.

    • Succession had the same two defects (dumped as succession first …, and the optional succession keyword was unconditional — first a then b; came back as succession first a then b;). Same fix, same flag. This is what made systems/Flows.sysml non-idempotent.

    • Library sweep (58 files) after the fix: 0 raw dicts, and the four Quantities/Geometry files plus systems/Flows.sysml are clean fixed points. Residual stragglers, each its own defect, are filed as #40: Actions.sysml (a succession's perform target is dropped → parse error), SampledFunctions.sysml (an indexed #(i) expression emits text the grammar rejects), VerificationCases.sysml (if cond ? whitespace not normalised), and the CaseUsage/AnalysisCaseUsage skips that print on dump.

    • Pins: tests/issue39_test.py (21).

    0.102.9 (2026-11-03)¶

    • Issue #38: multiple redefinitions lost their comma separator. redefines is a comma list, but Redefinitions.dump() joined the targets with a plain space:
    attribute :>> ThermodynamicTemperatureUnit::quantityDimension TemperatureDifferenceUnit::quantityDimension {

    which the grammar rejects. The whole attribute line then failed to load, so SI.sysml, USCustomaryUnits.sysml and ShapeItems.sysml were never re-parseable — even after the last of their raw-dict leaks was removed. Now :>> A::x, B::x, matching the source.

    • References (::>) had the mirror-image bug, one step behind it: that operator repeats per target (::> A ::> B) and the grammar rejects a comma list there, so its dump now repeats the operator instead of joining with a space.

    • Library round-trip: 3 of 4 files fixed. SI.sysml, SIPrefixes.sysml and USCustomaryUnits.sysml now dump → parse → dump with no change and no raw dicts. ShapeItems.sysml still is not a fixed point, and the remaining diff is entirely binding connectors — filed as #39 (binding [1] bind … loses its binding keyword and multiplicity, a captured-text artifact that only looked correct on the first dump).

    • Pins: tests/issue38_test.py (16).

    0.102.8 (2026-11-02)¶

    • Issue #33: grouped exponents were opaque text — calc bodies were unevaluable, and unit-expression exponents dumped raw dicts. A parenthesized group had no representation in the expression chain, so the emitter fell back to preserving the whole expression as one name: (x^(1/2)+0) reached the evaluator as the identifier (x^(1/2)+0). It is now represented structurally — a PrimaryExpression whose base is a SequenceExpression relationship, the shape BaseExpression.dump() already renders in parentheses — so the group is one operand of whatever encloses it:
    • (x^(1/2)+0) at x=9 → 3.0; (a+b)^2 → 25.0; (x*(1+y))^2 → 64.0; results stay pint-aware (x * 2 [m] → Quantity(6.0, 'meter')).
    • The #31 paren guards are gone: with a real paren node the emitter no longer needs a binding-power heuristic, and tp / (tm * v), -(2 - 5) and (a or b) and c all dump as written and are now structured rather than text.
    • Two dumper defects behind the raw-dict leak: ExponentiationExpression.dump() converted its right operand as another ExponentiationExpression (the grammar says unaryExpression), so x ^ 2 printed x ^ {'name': 'UnaryExpression', ...}; and MultiplicativeExpression.dump() joined operands with "" (tp/ (tm* v)). Both fixed.
    • const_fold folds through groups (nested OwnedExpression, SequenceExpression), and the evaluator accepts ^ (SysML spelling) as well as **.
    • Library effect: the four files that leaked dicts are clean — SI.sysml 1085 → 0, USCustomaryUnits 325 → 0, SIPrefixes 35 → 0, ShapeItems 104 → 0 — and dump without any stdout output.

    • Pins: tests/issue33_test.py (27).

    • Issue #32: keyword-less variant members kept their body at grammar level. variant 'six cyl' { attribute note : String; } built the variant element but loaded no children, because Reference.load_from_grammar returned before the shared body dispatch. The dispatch loop in Usage.load_from_grammar is now Usage._load_body_members, and the VariantReference branch unpacks its UsageBody → DefinitionBody members and loads them through it, so variant.children really holds the members.

    • Same gap in action bodies: variation action g : A { variant g1; } parsed as ActionBodyItem → VariantUsageMember, which neither the visitor nor Action.load_from_grammar dispatched — the variants existed only in the grammar. The visitor now visits VariantUsageMemberContext, and the action loader routes those members through the shared dispatch with the variant chain marked (is_variant True). On the OMG corpus this restores all four variant generateTorque*/amplifyTorque* members.

    • Pins: tests/issue32_test.py (9), including the OMG VehicleVariabilityModel round-trip.

    • New issue #38 filed (found here): multiple redefinitions are dumped space-joined without repeating :>>, which is why SI.sysml / USCustomaryUnits / ShapeItems still do not re-parse even with no raw dicts left.

    0.102.7 (2026-11-02)¶

    • Issue #31: assert constraint bodies dumped glued operators and never reached a fixed point. Three separate defects in the expression emitter — only the third was in the report:
    • Wrong operand class for the loose boolean layers. _unwrap_to_layer handed OrExpression the And-layer, XorExpression the Or-layer and ImpliesExpression the tail of a ladder, but each layer's grammar class expects the layer immediately BELOW it (orExpression : xorExpression (OR xorExpression)*). Any expression using or/xor/implies therefore put a foreign chain dict into an operand slot and the dumper stringified it: a xor b → a xor {'name': 'OrExpression', 'operator': [], ...}. Corrected for OR (→ xor), XOR (→ and) and IMPLIES (→ or).
    • Parenthesized groups never entered the chain. (A and B) xor (C and D) matched no emitter branch, so the whole expression collapsed to one FeatureReference name. Groups are now unwrapped (_paren_inner_context, which follows the ownedExpression → primaryExpression → baseExpression → '(' sequenceExpressionList ')' wrappers). A group keeps its parens whenever its loosest operator binds no tighter than the enclosing operator — at equal precedence the parens still decide the grouping (tp / (tm * v) must not become tp / tm * v, -(2 - 5) must not become -2 - 5), and a unary prefix over a grouping stays text for the same reason.
    • The text fallback glued tokens. ctx.getText() concatenates tokens, so any preserved expression became unparseable ((a or b) and c → (aorb)andc). The fallback now slices the original source (_verbatim_text, whitespace-normalised) using the context's character interval, so preserved text is the source text.
    • Dumps no longer print on stdout. valid_definition printed the offending dict's name before raising — on a normal control-flow miss (probing an operand against several layer classes). It flooded sysmlpy ci with layer names; the raise stays, the print is gone.
    • Corpus: VehicleVariabilityModel.sysml (the reporting file) now reaches a fixed point with no language "English" capture and an operator sequence identical to the source (21 operators, ==/and/xor).
    • Gate: 0 parse failures, 1180 errors (was 1183) / 1706 warnings, PASS — the three former text-captured bodies now expose their identifiers to the resolver, retiring 5 UNRESOLVED_EXPRESSION_IDENTIFIER findings.
    • Pins: tests/issue31_test.py (11). Known and unchanged: unit-expression exponents (s ^ -1, 1024 ^ (1/1000)) still dump their UnaryExpression dict — a pre-existing leak tracked by issue #33, which the same machinery now makes tractable.

    0.102.6 (2026-11-02)¶

    • Issue #34 step 7: the .kerml half of the library now answers on truth. KerML names were only ever scraped — exists_in_loaded_model returned False for them by design, library_namespace_table filtered its candidates to .sysml, and the regex index carried doc-comment words as names.
    • KerML has no public Model loader, but its parse_to_dict output is already name-shaped (name = the declaration KIND, declaredName / declaredShortName = identifiers, children = nested members). A symbol table is now built directly from that dict (LibrarySymbolIndex._kerml_table_for_file, process-cached), so VectorFunctions, VectorValues, ScalarValues, Collections … answer with their real members; declarations are represented by a minimal _LibrarySymbol (name, kind, typed_by, shortname) because there is no model element to hand back.
    • library_namespace_table accepts .kerml candidates, so private import VectorFunctions::* imports real members; the scraped index stays only as the callers' last fallback.
    • exists_in_loaded_model consults the KerML table for fingerprinted .kerml sources (nested members included), so exists_in_loaded_model( "VectorOf") is True instead of False-with-a-scraped-fallback.
    • The leaf fingerprint now harvests .kerml declarations lexically (_KERML_DECL_RE, leading modifiers included: abstract datatype VectorValue, in feature v), so the step-7 path works in a cold process that has not built the full symbol index. Before this the kerml leaves existed only as a side effect of the index walk, and a step-7 lookup in a fresh process silently found no candidates.
    • Gate unchanged by design: 0 parse failures, 1183 errors / 1706 warnings, PASS, identical per-code histogram to 0.102.5 — the scraped fallback was already resolving these names on the corpus, so step 7 changes how they resolve (truth, without doc-comment noise), not how many.
    • Pins: tests/issue34_step7_test.py (7 — member tables, kernel namespaces, the symbol stand-in, exists_in_loaded_model, nested members, absence of doc-comment words, and an import resolving through the table). Two older pins updated to the new truth (library_model_test, issue34_step5_test).

    0.102.5 (2026-11-02)¶

    • Issue #34 step 5: imports resolve against the loaded library model. Phase 1+2 (0.102.0) made the existence question answer on truth; this release does the same for import visibility — a private import SI::* imports the members the loaded SI model really declares, including declared short names (attribute <kg> kilogram), which no scraped name list carried.
    • SymbolTable._walk_element registers declared short names for every element (not just library ones), so attribute <x> foo : Real; makes x a real name in its own namespace too.
    • SymbolTable.lookup_member/table descent unchanged; the library table is built shallow (direct members, no recursive import walk) and cached per namespace. A table that resolved its own imports walked the whole library closure: 248 s cold on a two-import model, which is why the earlier attempt was deferred. Shallow costs ~1–2 s per namespace (DFA-warm) and leaves a facade's re-exported members to exists_in_loaded_model — they still resolve as references (the residual is the import-suggestion warning for a re-exported name, documented below).
    • Re-entrancy guard (_namespace_table_building) so two library files that import each other cannot loop; .kerml-only namespaces (e.g. VectorFunctions) keep the scraped fallback unchanged (step 7 will model-load them).
    • Gate delta (bundled library + fixtures, 99 files): errors 3369 → 1183, warnings 2961 → 1706, PASS, 0 parse failures. Per-code: UNRESOLVED_EXPRESSION_IDENTIFIER 3180 → 1006, IMPLICIT_LIBRARY_IMPORT 2598 → 1343, UNDEFINED_SYMBOL 58 → 46; every other code unchanged (nothing increased, nothing suppressed).
    • Cost: a cold analyze on a library-importing model 28.9 s → 39.5 s (the table builds for the imported namespaces); warm analysis unchanged (~0.0 s). Persisting tables across processes (step 6) is now a cost-optimisation, not a prerequisite.
    • Pins: tests/issue34_step5_test.py (7 — unit short names, facade truth fallback, short names in the table, element-valued members, the .kerml fallback, user-model short names, and a namespace no library defines still warns).
    • Plan record updated: docs/v0.102-library-model-resolution.md.

    0.102.4 (2026-11-02)¶

    • Issue #29: interface ends are first-class children and keep their typing. interface def I { end e1 : PD; end e2 : PD [1..*]; } built the Interface with zero children, kept the ends only in Interface.ends as (name, None, None), and dumped end e1; — the declared type, multiplicity and flags were gone from the model and the text.
    • New public element InterfaceEnd (also exported as sysmlpy.InterfaceEnd): name, typed_by_name, multiplicity (as written, e.g. [1..*] / [0..1] ordered nonunique), reference (the ::> a.b chain as written), plus typed_elements / reference_elements lazy resolution (the issue #23 *_elements rule: unambiguous names only). Ends appear in iface.children; iface.ends / iface.iface_connections keep their old shapes, now with the type filled in.
    • Interface.load_from_grammar reads the : T typing (Typings → TypedBy) and the multiplicity part (bounds plus ordered/nonunique) that it previously dropped.
    • The rebuild that serializes an interface body (Usage._ensure_body) emits each end through one shared builder (_interface_end_body_item) in the visitor's own shape (InterfaceBodyItem → InterfaceOccurrenceUsageMember → InterfaceOccurrenceUsageElement → DefaultInterfaceEnd → Usage), with the Typings and ::> chain specializations and a rebuilt MultiplicityPart — so the body no longer degrades on every dump and dump → parse → dump is a fixed point. Children take precedence; the self.ends path remains for programmatic add_end().
    • Dump glue: InterfaceUsageDeclaration carried a literal newline in its connect keyword, so interface ib connect a to b; came out as connect\\n a to b;.
    • Fixed en route (pre-existing, proved on 0.102.3): a programmatically built Interface raised AttributeError: 'NoneType' object has no attribute 'get_definition' from Model.dump() because Interface.grammar stayed None; Interface._get_definition now synthesizes a body-less grammar object.
    • Pins: tests/issue29_test.py (7 — reporter model, typing in the dump, multiplicity/flags round trip, ::> chain, usage-with-body, single-line connect, programmatic definitions and usages).
    • Gate unchanged: 0 parse failures, 3369 errors / 2961 warnings, PASS. Affected suites 713 passed; full suite 1822 passed / 79 skipped.

    0.102.3 (2026-11-01)¶

    • Issue #35: the KerML parser shares the persistent DFA cache. dfa_cache covered only the SysML parser, so every KerML corpus run and every library-index walk re-derived the prediction structures cold (Occurrences.kerml ~14 s per parse, every process).
    • The cache is now per grammar family: each target has its own key and file, derived from its own serialized ATNs (plus ANTLR runtime + version), so a SysML grammar change can never invalidate or corrupt the KerML cache and vice versa. SysML keeps its historical dfa-<key>.pkl name (caches written by earlier releases stay valid); KerML writes dfa-kerml-<key>.pkl.
    • A target is only loaded/saved when its parser actually ran in the process (used), so a SysML-only run never imports the KerML classes or touches its file.
    • Exit-time re-save: the once-per-process save landed after the FIRST parse of a run, so a library-index walk persisted 558 of the 1,622 states it warmed. maybe_load/maybe_save now register an atexit hook that re-saves each used target when its in-process DFA is strictly warmer than the file — the multi-file walk converges instead of half-caching.
    • Measured (fresh processes, bundled library): LibrarySymbolIndex.get_symbols 51 s → 26 s; the analysis that follows a warm index 59 s → 1.7 s; Occurrences.kerml 13.7 s → 3.3 s; full test suite 34m44s → 23m04s.
    • dfa_cache API: cache_key/cache_file/load_dfa_cache/save_dfa_cache/ maybe_load/maybe_save/stats take an optional target ("sysml" default, so every existing call and cache stays valid); targets() lists the families. Cache problems still never break a parse (maybe_* swallow).
    • Fixed en route: the generated parsers define serializedATN() at MODULE level — keying on the class attribute raises AttributeError, which the new _serialized_atn() resolves (module first, class fallback).
    • Docs: README's "Parse Performance and the DFA Cache" now covers both grammars and the measured numbers.
    • Pins: tests/issue35_test.py (7 — per-target keys/files, save→load, the SysML/KerML file isolation, the disable flag, the never-raise contract, and a subprocess pin that the exit hook persists the whole corpus walk). The dfa_cache_test monkeypatch of cache_file accepts the new target keyword.
    • Gate unchanged: 0 parse failures, 3369 errors / 2961 warnings, PASS. Full suite 1815 passed / 79 skipped.

    0.102.2 (2026-11-01)¶

    • Issue #30 (reported downstream by the CARTA team): allocation usages and definitions keep their body members. allocate p to q { attribute note : String; } built the Allocation element with zero children — the body member was absent from the model, and the dump kept it only by re-serializing the parsed grammar — so a consumer reading allocations (their repro_01) saw nothing inside them. No exception, no visitor warning.
    • Visitor: allocationUsage hardcoded an empty DefinitionBody — the same defect the connection fix closed in 0.99.5. It now fills the body through the shared usageBody helper (_connection_usage_body_items, whose docstring now records that allocationUsage has the same shape).
    • Loaders: all three sites assigned element.grammar directly instead of calling load_from_grammar, so nothing was ever flattened — the package-level definition and usage (definition.py), the nested usage in a definition body, and the behavior-body path (usage.py). All four now use the shared loader.
    • Dump: AllocationUsage.dump joined unstripped parts, emitting allocate p to q { (double space); it now strips like its base class.
    • Serialization safety: a parsed allocation keeps its parsed body authoritative (Allocation._ensure_body returns early), because rebuilding from children loses what no child models — redefinition-carrying ends (end :>> source : Wheel;, the 0.98.1/PR#18 pin) and inner allocate source.xs to target.y; statements. Programmatic elements still rebuild from children as before.
    • Pins: tests/issue30_test.py (6 — usage body, definition body, nested usage, visitor-dict body, dump→parse→dump fixed point, empty bodies unchanged).
    • LSP subprocess test budget 120 s → 300 s, with the cost documented. The end-to-end test spawns a cold server that pays the scraped library index (.kerml parse, ~55 s; #35 caches it) plus the first SI.sysml load (~60 s when the DFA cache has no entry for that family — the cache file is keyed by the sysmlpy version, so the first run after every release is cold). It passed at 119.9 s against a 120 s timeout: a latent flake, not a measurement. No analysis-cost change.
    • Verified: affected suites 527 passed; gate unchanged (0 parse failures, 3369 errors / 2961 warnings, PASS); full suite 1808 passed / 79 skipped.

    0.102.1 (2026-10-31)¶

    • Issue #37 (reported by failys): qualified references into an IMPORTED namespace resolve. ::> type = InterfaceType::required; — with InterfaceType visible only through private import LIB::* — was reported as UNRESOLVED_EXPRESSION_IDENTIFIER, twice per use (the value-owning Port and the redefining Reference).
    • Root cause: the qualified-name descent resolved the head name, then asked _find_symbol_owner(head) — which answers where the name is visible (the importing scope) — and looked for the namespace in that scope's _children. An imported namespace's member table belongs to its DEFINING package (LIB::InterfaceType), so the descent never reached required.
    • Fix: SymbolTable records element → member-table at build time (_element_scopes, kept on the root table; _scope_for_member consults it after the existing child/owner lookups), and all three descents use it (_resolve_qualified_name, _find_namespace_table, _is_resolved). The final segment stays "the resolved element" — no child namespace is required for it.
    • Not leniency: a bogus member (E::nope) is still reported, and the reporter's model validates clean under Open-MBEE's OpenSysML (-validate -strict), confirming the finding was ours.
    • Pins: tests/issue37_test.py (5 — the reporter's model, named-import and same-package forms, the negative case, and a symbol-table pin that the resolver returns the EnumeratedValue member).
    • Gate unchanged: 0 parse failures, 3369 errors / 2961 warnings, PASS (identical per-code histogram — the pattern does not occur in the bundled corpus). Affected suites 372 passed; full suite 1802 passed / 79 skipped.

    0.102.0 (2026-10-31)¶

    • Issue #34 (phase 1+2): the analyzer's library fallback resolves through loaded library MODELS, not the scraped name index.
